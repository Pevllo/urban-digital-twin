# Trip Demand Model — AI Urban Digital Twin

Road-level hourly traffic volume prediction for the **AI Urban Digital Twin + What-If Simulator**. The model predicts `traffic_volume` for each OpenStreetMap (OSM) road segment using static road/network attributes and calendar features. It is designed as the prediction core of a future "What-If" road-network simulator.

The synthetic data-generation pipeline (zones, OD matrix, OSM mapping, traffic assignment) is treated as the **source of truth — never regenerated by this ML stage.**

---

## 1. Purpose

- **Traffic Volume Prediction**: Estimate hourly vehicle volumes across individual road network links based on spatial, topological, and temporal features.
- **What-If Simulation Entry Point**: Given a (possibly modified) road network and a timestamp, estimate traffic volume without re-running the full traffic assignment.

---

## 2. Inputs

### Raw Dataset

- `data/raw/traffic_ml_dataset.csv.gz` — 8,506,000 rows × 22 columns
  - 4,253 roads × 200 days × 10 sampled hours
  - Period: 2024-01-01 to 2024-07-18
  - Sampled hours: {0, 3, 6, 7, 8, 9, 12, 15, 18, 21}

### Input Features (30 numeric + 1 categorical)

| Feature | Category | Description |
|:---|:---|:---|
| `hour` | Temporal | Hour of day (0–23) |
| `day_of_week` | Temporal | Day of week (0=Mon … 6=Sun) |
| `month` | Temporal | Month (1–12) |
| `hour_sin`, `hour_cos` | Temporal | Circular encoding of hour |
| `dow_sin`, `dow_cos` | Temporal | Circular encoding of day-of-week |
| `is_weekend` | Temporal | 1 if Fri/Sat (Egyptian work-week) |
| `is_peak_hour` | Temporal | 1 if hour ∈ {7,8,9,17,18,19} |
| `morning_peak` | Temporal | 1 if hour ∈ {7,8,9} |
| `evening_peak` | Temporal | 1 if hour ∈ {17,18,19} |
| `road_length_m` | Road | Segment length in meters |
| `road_length_log` | Road | log1p(road_length_m) |
| `lane_count` | Road | Number of lanes |
| `speed_limit_kmh` | Road | Speed limit (km/h) |
| `lane_speed_product` | Road | lane_count × speed_limit_kmh |
| `lane_length_product` | Road | lane_count × road_length_m |
| `speed_length_product` | Road | speed_limit × road_length_m |
| `is_oneway` | Road | 1 if one-way road |
| `is_bridge` | Road | 1 if bridge segment |
| `is_tunnel` | Road | 1 if tunnel segment |
| `node_degree` | Network | Degree of nearest node |
| `connected_road_count` | Network | Number of connected roads |
| `node_degree_log` | Network | log1p(node_degree) |
| `connected_road_log` | Network | log1p(connected_road_count) |
| `roadlen_hour` | Interaction | road_length × hour |
| `dow_hour` | Interaction | day_of_week × hour / 24 |
| `lane_is_peak_num` | Interaction | lane_count × is_peak_hour |
| `speed_is_peak_num` | Interaction | speed_limit × is_peak_hour |
| `highway` | Categorical | OSM highway class (13 levels) |

### V2 Extended Features (36 total)

Adds 7 network features (`from_node_degree`, `to_node_degree`, `node_connectivity_min/max`, `hierarchy_level`) and 7 temporal interactions (`lanes_peak`, `speed_peak`, `length_x_hour`, `highway_hour/peak/weekend`, `dow_hour`).

## 4. Data Pipeline

```
Raw Data
  │  data/raw/traffic_ml_dataset.csv.gz
  │
  ▼
Preprocessing (src/feature_engineering.py)
  │  Drop constant/redundant columns
  │  Verify no missing values, duplicates
  │  Apply Egyptian weekend convention (Fri/Sat)
  │
  ▼
Feature Engineering (src/feature_engineering.py)
  │  Circular encodings, log transforms
  │  Interaction terms, network topology
  │  → data/processed/traffic_ml_clean.csv / .parquet
  │
  ▼
V2 Feature Extension (src/build_features_v2.py)
  │  Additional road/network/temporal interactions
  │  → data/processed/traffic_ml_features_v2.parquet
  │
  ▼
Model Training (src/train_models.py)
  │  Chronological split (train/val/test)
  │  Baselines → LR → RF → XGBoost
  │  → models/traffic_xgboost_model.json
  │
  ▼
Experiment Pipeline (src/run_experiments.py)
  │  Feature ablation, log-target, tuning
  │  Two-stage zero-inflated, ensemble
  │  → data/experiments/
  │
  ▼
Prediction
  │  Load XGBoost Booster → inplace_predict(X[features])
  │  What-If: modify road attributes → re-predict
```

## 7. Inference

```python
import xgboost as xgb
import pandas as pd
import json

# Load metadata and model
meta = json.load(open("models/preprocessing_metadata.json"))
booster = xgb.Booster()
booster.load_model("models/traffic_xgboost_model.json")

# Prepare input DataFrame X with required columns
# X must contain all features listed in meta["features"]
X["highway"] = X["highway"].astype("category")

# Predict
pred = booster.inplace_predict(X[meta["features"]])
```

For the V2 feature set (36 features), use `data/processed/feature_metadata_v2.json` instead.

## 13. Key Decisions

- **Leakage**: `volume_capacity_ratio` / `congestion_level` were target-derived and excluded upstream; audit in `reports/leakage_audit.md`.
- **Cleaning**: Dropped constant `intersection_density`, redundant ordinal `highway_code`; no missing values or duplicates.
- **Encoding**: Native categorical for XGBoost, one-hot for LinearRegression/RandomForest — no arbitrary ordinals.
- **Split**: Chronological (train Jan–Apr, val May–mid-Jun, test mid-Jun–Jul). Validation drives all model selection; test set touched once per candidate.
- **`is_weekend`**: Fri/Sat convention (Egyptian work-week) — matches observed demand dip.
- **No lag features**: Dataset has none; model = road traits × calendar profile, suitable for hypothetical networks in What-If simulation.
- **MAPE excluded**: 36.8% zero-volume rows make percentage error mathematically undefined.
